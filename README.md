# Проектирование Telegram-бота «ЖК-Паркинг» 🚗

Репозиторий содержит системные требования, архитектуру данных и прототип сервиса для аренды парковочных мест в жилом комплексе.

1. Бизнес-требования (User Stories)
Как Владелец, я хочу зарегистрировать свое парковочное место в боте (указать номер и уровень), чтобы сдавать его.
Как Владелец, я хочу указывать даты и время, когда мое место свободно, чтобы робот автоматически предлагал его в аренду.
Как Владелец, я хочу получать уведомления, когда мое место забронировали, чтобы быть в курсе.
______________________________________
Как Арендатор, я хочу видеть список свободных мест на нужную мне дату и время, чтобы выбрать подходящее.
Как Арендатор, я хочу забронировать место в два клика, чтобы быстро припарковаться.

2. Логика процессов (Workflow)
Процесс бронирования парковки Арендатором:
1. Старт -> Запуск бота.
2. старт
запуск бота
предлагается выбрать дату и время
бот проверяет наличие свободных мест на выбранную дату
развилка
если есть места, то показывает список мест, пользователь выбрал место из представленного списка, он жмет на кнопку забронировать,
после бот подтверждает бронь
если нет то выводит, что мест на выбранную дату и время нет, предлагает изменить параметры
конец

3. Архитектура данных (СУБД: SQLite)
Структура таблицы `parking_spots`:
* `spot_id` — Уникальный номер места (Primary Key)
* `spot_number` — Номер места
* `level` — Этаж (-1 или -2)
* `owner_id` — ID владельца

Пример SQL-запроса для поиска мест на конкретном этаже:

SELECT * FROM parking_spots WHERE level = -1;
